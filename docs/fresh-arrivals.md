# Свежие поступления из 1С

## Обязательный алгоритм опта

На `opt.globalmarket.kg` раздел `group-fresh-arrivals` / «Свежие поступления»
всегда является первым, виртуальным и непустым. Он не создаёт копии товаров:
те же ID одновременно остаются в исходных разделах 1С и используют общий
остаток, цену и состояние корзины.

Алгоритм отбора утверждён владельцем:

1. крупное оприходование — строго больше 10 000 USD;
2. отсчёт начинается с последнего крупного оприходования;
3. предыдущие крупные оприходования присоединяются, пока каждый разрыв между
   соседними крупными документами не превышает 14 календарных дней;
4. первое более раннее крупное оприходование за пределами 14 дней служит
   границей и в раздел не входит;
5. все мелкие оприходования новее этой границы входят в раздел;
6. независимо от пунктов 1-5, в раздел также входят все оприходования за 30
   календарных дней до самой поздней известной даты оприходования включительно;
7. два набора документов объединяются без дублей;
8. из выбранных документов показываются только позиции с текущим положительным
   остатком; порядок — сначала порядок документов, затем текущая позиция 1С;
9. обновление только остатков повторно фильтрует последний проверенный набор и
   не имеет права удалить раздел.

Перед расчётом объединяются все последовательные проверенные снимки отчёта 1С и
отдельные документы оприходования. Новый накопительный отчёт может не содержать
старый документ, отдельный код товара или полную цену строки, поэтому он не
заменяет историю: документы и коды объединяются. Сумма отдельного документа
оприходования считается авторитетнее оценки из накопительного отчёта; если
отдельного документа нет, сохраняется максимальная полная наблюдавшаяся сумма.

Если нового полного отчёта с документами оприходования нет, используется весь
последний проверенный набор отчётов и его общий SHA-256. Дата файла остатков,
возврат товара на склад и изменение количества сами по себе не делают товар
новинкой.

Сборка выполняется `scripts/opt_fresh_arrivals.py`. Перед публикацией обязателен
`scripts/verify_opt_fresh_arrivals.py`: он проверяет первый раздел, 30-дневное
окно, актуальность отчётов и отдельных документов, порядок отбора, положительный
остаток, сохранность всех карточек и неизменность 16 исходных разделов 1С.

## Правило витрины

Основной источник блока «Свежие товары» — точный порядок виртуального раздела
`Свежие поступления` оптового каталога того же релиза. В розничный каталог этот
порядок переносится `scripts/apply_retail_fresh_arrivals.py` полями
`freshArrival: true` и `freshArrivalRank`, без изменения исторических дат
карточки. `scripts/verify_retail_fresh_arrivals.py` блокирует публикацию, если
набор, порядок или любые посторонние поля розничного каталога отличаются.

Для розничной сборки, если соответствующая оптовая проекция ещё не подготовлена,
разрешён временный fallback: только позиции, чей стабильный персональный код 1С
впервые появился в последней выгрузке остатков. Этот fallback недопустим для
публикации оптового сайта. Изменение названия, цены, количества или возврат товара
на склад не делает существующий товар новым.

- `firstSeenAt` — дата первого появления стабильного кода 1С;
- `latestStockDate` — дата последней импортированной выгрузки;
- при наличии `freshArrival` используется только явный список и его ранг;
- иначе товар попадает в блок, только если `firstSeenAt == latestStockDate`;
- старые записи без достоверной даты первого появления остаются без даты;
- если новых кодов в выгрузке нет, блок скрывается;
- `restockedAt` хранится отдельно и не определяет новизну товара.

## Идентичность товара

Основной идентификатор — персональный код позиции из 1С (`source_code`). Название
можно исправлять и дополнять без создания нового товара. Импорт сопоставляет строку
по стабильному коду и сохраняет прежний `first_seen_at`.

SQLite-таблица `source_products` получила колонку `first_seen_at`. При первом
импорте нового кода она получает дату отчёта 1С. При повторных импортах дата не
изменяется. Для существующей старой базы миграция добавляет колонку, но не ставит
сегодняшнюю дату всем старым товарам.

## Порядок показа

Новые позиции группируются по типу и выдаются круговым проходом. Приоритет начала:

1. порошок;
2. шампунь;
3. дезодорант или антиперспирант;
4. зубная щётка;
5. остальные типы товара.

После одной позиции из каждого доступного типа начинается следующий круг. Поэтому
варианты одной линейки не занимают всю карусель, а клиент сразу видит ассортимент
из разных разделов. Внутри каждого типа выше ставятся товары с фотографией, затем
по рейтингу и названию.

## Пополнение остатка

`restockedAt` продолжает обновляться отдельно, когда количество товара выросло или
товар вернулся с нулевого остатка. Поле можно использовать для внутренней аналитики
и сортировки пополнений, но не для публичного блока «Свежие товары».

## Поток данных

1. `scripts/import_stock.py` читает выгрузку 1С и сохраняет `first_seen_at`.
2. `generate_outputs()` пишет `firstSeenAt` и `latestStockDate` в
   `data/catalog.json`.
3. `scripts/build_public_catalog.py` переносит поля в публичный каталог.
4. `app.js` выбирает только новые активные позиции и чередует их по типам.

Правило начнёт наполнять блок после следующего реального импорта 1С. Текущим старым
товарам дата первого появления намеренно не назначается задним числом.
